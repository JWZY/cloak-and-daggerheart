# Cloak & Daggerheart — Review (April 2026)

A structured critique of the project against (a) the **official Demiplane Nexus character builder** for Daggerheart and (b) the **Daggerheart SRD v1.0**. Source-of-truth research lives at `/research/daggerheart-builder-reference.md` in the reviewer's notes (sources cited inline below).

This file is a snapshot. Live tracking is in the open draft PRs under `docs/proposals/`.

---

## What's working

- **Visual identity is stronger than any other Daggerheart builder I've reviewed.** Liquid-glass surfaces, gold-on-dark, EB Garamond small-caps, ember overlay tied to class accent color. Reads as Daggerheart, not as a generic D&D sheet palette-swapped.
- **Card-as-character metaphor.** Hero + domain hand makes the table experience the primary interaction, not a form. This is a real wedge against Demiplane.
- **iOS-native feel.** Vaul sheets, spring physics, safe-area insets, 44pt touch targets, hold-to-delete with progress fill. Designer-quality.
- **Accessibility scaffolding.** `role="dialog"`, `aria-modal`, focus restoration, Escape handling. Better than most hobby projects.
- **Engineering hygiene.** Zero-warning ESLint, Vitest + Playwright, persisted Zustand, PWA. Clean separation between `core/` and React.

## Reality check on README

The README claims "Built-in duality dice roller with Hope/Fear mechanics". The roller logic exists in `core/dice/`, but in `HandView.tsx` the Actions tab is `<p>Actions panel coming soon</p>`. Either restore the UI or update the README. (See [proposal: dice-roller-ui](./proposals/dice-roller-ui.md).)

## Feature gaps vs. Demiplane Nexus

Demiplane is the official partner builder for Daggerheart (browser-only, free for builder + sheet, paid for full Core Rulebook content). What it does that this project does not:

| Area | Demiplane | This project | Gap |
|---|---|---|---|
| Dice roller (click trait/weapon/feature → Duality popup with advantage/experience toggles) | Yes | Logic only, no UI | **Blocker** |
| Roll log / history | No (community complaint) | None | Differentiator opportunity |
| Loadout vs. Vault, 5-card cap, Recall Cost | Yes | Flat `domainCards[]` | **Blocker at L2+** |
| Scars (Avoid Death → cross out a Hope slot permanently) | Yes | Not modeled | Parity |
| Damage threshold flow (HP click → asks for damage → marks correctly) | Yes | Drag bar previews, never commits | Parity |
| Stress → HP overflow (mark 1 HP if stress full) | Implicit (rules-correct) | Clamps at max | **Rules bug** |
| Auto-Vulnerable when last stress slot marked | Implicit | Free-form conditions | **Rules bug** |
| Mixed Ancestry (top of one, bottom of another) | Yes | Single-pick only | Parity |
| Multiclassing (L5+) | Yes | Missing from `AdvancementType` | Parity |
| Death moves (Blaze of Glory / Avoid Death / Risk It All) | Yes | None | Parity |
| PDF export, shareable link, QR code | Yes | None | Parity |
| Edit-by-Others (real-time co-edit) | Yes | None | Out of scope |
| Roll20 sync | Yes | None | Out of scope |
| Custom portraits | Upload + presets | `setPortrait` exists, no UI | UX gap |
| Compendium / rules tooltips | Yes | None | Nice-to-have |

## Rules-correctness bugs

These will silently produce wrong characters or wrong session state. SRD references in linked proposals.

1. Stress overflow not modeled. SRD: "If forced to mark Stress while full, mark 1 HP instead."
2. Vulnerable not auto-applied when stress hits max.
3. Hope cap of 6 not enforced. `StatBar` passes `showMax={false}` and the store has no upper clamp.
4. Mixed Ancestry rule missing (top feature of one + bottom of another).
5. Starting inventory empty. SRD requires torch, 50ft rope, basic supplies, 1 handful gold, choice of Minor Health **or** Stamina Potion, plus class-specific item.
6. Gold model wrong. SRD: Handfuls / Bags / Chests with 10:1 rollover.
7. Damage-threshold bar previews "Mark 2 HP" but never writes it.
8. Multiclass missing from `AdvancementType` union; half-level domain card rule unhandled.
9. `markedTraits` field exists but no UI to mark them, no tier-2/5/8 clear-all behavior, no lock against re-+1ing the same trait inside a tier.
10. Proficiency multiplier on weapon damage not verified end-to-end. SRD: Proficiency multiplies *dice count*, not flat modifier.
11. Loadout cap of 5 not enforced; subclass/ancestry/community cards must not count toward it.
12. Recall Cost not surfaced or used when swapping cards out of rest.
13. Death moves not implemented. When last HP slot is marked, the sheet should offer Blaze / Avoid / Risk-It-All.

## UX / design polish

### What's not working

1. **Actions tab stub.** "Coming soon" placeholder in shipped UI is a credibility tax. Hide the tab or wire the dice roller.
2. **Three trait-assignment variants behind a dev toggle.** Pills, Stepper, Cycle. Pills is correct (matches SRD's pre-defined array). Stepper implies traits can be any value, which they can't at creation. Ship Pills, delete the rest.
3. **Card-metaphor vocabulary leaks into navigation.** "Deck Builder," "Hand View," "Hero Card." Daggerheart's own words are **Loadout** and **Character Sheet**. Use the game's vocabulary in nav; reserve the card metaphor for the visual layer.
4. **Wizard step order vs SRD order.** Class-first is defensible (matches Demiplane's screen flow per Alphastream's June-2025 walkthrough). Document the rationale; don't rearrange without reason.
5. **Damage-threshold bar.** Beautiful interaction, wrong commitment model. Hover/drag should preview, click or pointerup should commit.
6. **Gear menu hierarchy.** Short Rest, Long Rest, Level Up, Edit, Delete are all rendered as sibling menu items at different lifecycle frequencies. Surface Short/Long Rest as primary actions; bury Edit/Delete in Settings.
7. **Custom portraits.** `setPortrait(dataUrl)` exists in the store but no UI lets a user pick or upload one.
8. **Empty state / first-run.** No dedicated character-select surface beyond an empty directory. First-run is the highest-leverage UX moment for a hobby app.
9. **Step carousel labels.** Carousel shows position but not what each step *is*. Persistent labels make the wizard skim-able.
10. **Microcopy is inconsistent.** "Begin Adventure" is in-world; "Heavier armor raises damage thresholds…" is technical. Pick one register.

---

## What we're explicitly not chasing

- **Realtime party sync** (Firebase / PartyKit / etc.). Demiplane's Edit-by-Others is genuinely good and not a hobby-project win.
- **Roll20 integration.** Same reason.
- **Homebrew card editor.** Demiplane will ship one and out-feature any independent attempt.

The wedge is *the play experience feels like the game*. Lean there.
